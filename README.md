# 留痕 · 数据保留追踪台

纯前端的演练样例：导入虚构数据集与副本位置，列出即将过期与待处理项，按数据版本生成删除计划，记录逐位置回执，并以时间线与差异导出留痕。**不连接任何真实存储，也不实际删除任何样例。**

## 运行

```bash
npm install
npm run dev     # http://localhost:5173
npm test        # 16 条领域规则测试 + 4 条界面冒烟测试
npm run build   # 类型检查 + 生产构建
```

## 规则怎么落到代码里

| 需求 | 实现 |
| --- | --- |
| 导入数据集 / 期限 / 副本位置 | 总览页「导入虚构数据集」；每个选中位置各生成一条副本记录 |
| 即将过期与待处理项 | 「即将过期与待处理」页；未清空且 14 天内到期（含已过期）的版本进入图表与队列 |
| 按版本记录目标副本与逐项结果 | 删除计划内「逐副本结果」按每个当前副本标注：法律保留 / 已确认 / 失败 / 未排入 / 待执行 |
| 任一副本失败不得显示彻底删除 | 覆盖度按版本的全部当前副本计算；有任一未确认时结论固定为「不得显示完成」并列出未确认来源 |
| 重复请求复用任务 | 以版本 + 当前副本集合为键；重复请求只累加 `requestCount` 并追加事件，不新建任务 |
| 后来发现新副本 → 重新待办 | 新副本并入现有任务，覆盖度立即下降；原回执保留可查 |
| 期限延长取消未执行计划 | 延长时取消尚无回执且未运行的计划，事件与审计留痕；已执行计划与回执不动 |
| 法律保留不进入执行 | 处于保留的副本排除在可执行集合；解除保留后按当前期限重新生成待办 |
| 每个位置单独回执 | 回执按位置 + 尝试序号生成，仅追加不清空；失败历史始终可查 |
| 只有全部当前副本确认才显示完成 | 完成判定要求全部当前副本的最新回执成功或状态为已删除 |
| 进度 / 时间线 / 差异导出 | 计划进度条与事件流、「时间线」页、「差异与导出」页（可导出 CSV） |

## 结构

- `src/domain/` — 纯函数领域引擎（`engine.ts`、`diff.ts`、`time.ts`）、种子数据 `seed.ts`
- `src/ui/` — 页面、元件与会话快照（`store.ts`）
- `tests/engine.test.ts` — 覆盖上述规则的单元测试
- `tests/app.test.tsx` — 界面冒烟：结论文案、逐副本结果、导入校验、时间线留痕
